This week I spent most of my time on three things: retries in distributed systems, running small language models locally, and fixing my weekly review routine.

## Distributed systems

Retries are only safe when the operation is idempotent. Before adding a retry, I now ask one question: what happens if this request runs twice?

- Use an idempotency key for every write that crosses a service boundary.
- Add jitter to backoff so clients do not retry in lockstep.
- Put a hard cap on total retry time, not just on the number of attempts.

## Local models

Small models running on a laptop are good enough for summarising logs and drafting test cases. They are not good enough to trust without review, so the output goes through the same code review as everything else.

```kotlin
fun backoffMillis(attempt: Int, baseMs: Long = 200, capMs: Long = 10_000): Long {
    val exp = minOf(capMs, baseMs shl attempt)
    return (0..exp).random()
}
```
