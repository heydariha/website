## Code review habits

Small pull requests get better reviews. When a change grows past a few hundred lines, I split it by behaviour, not by file.

> A review comment should say what to change and why, in one or two sentences.

## Structured outputs

Asking a language model for JSON that matches a schema, then validating it, turns a fuzzy tool into a predictable component. Validation failures are logged and retried once, never silently accepted.
